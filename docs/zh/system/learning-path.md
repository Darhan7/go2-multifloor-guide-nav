# 怎样使用这份教程：边实践，边把原理学明白

这套网站不是把“理论”和“操作”分成两本互不相干的手册。更合适的阅读方式是：**做到哪一步，就把这一步必须理解的知识一起弄清楚**。这样，命令不再是一串需要记忆的字符，代码也不只是“照着运行就行”。

## 每个实践页面都按同一条思路展开

1. **当前任务**：这一阶段最终要得到什么；
2. **先把概念讲清楚**：相关名词、数据结构和运行机制到底是什么；
3. **真实操作**：使用项目中实际执行过的命令、脚本和配置；
4. **代码怎样工作**：对象由谁创建、输入输出是什么、回调或 action 怎样被触发；
5. **为什么这样设计**：解释工程取舍，而不是把当前参数包装成唯一答案；
6. **怎样确认成功**：从进程、topic、TF、文件、图片和机器人行为多个层面验证；
7. **出现问题时先查哪里**：沿数据流寻找第一个不符合预期的位置；
8. **官方资料与另一条学习路线**：把当前实践接回 ROS 2、Nav2、Unitree 和其他 Go2 教程。

## 根据基础选择入口

### 第一次接触 ROS 2

建议先按顺序阅读：

```text
系统架构
→ ROS 2 基础概念
→ TF 与坐标系
→ 如何阅读代码
→ VMware 双网卡
→ 点云与地图数据模型
→ 地图采集
→ AMCL 与 Nav2
```

不要求提前掌握 SLAM 或概率机器人学，但最好会使用终端、能读简单 Python，并知道 IP 地址和文件路径是什么。

### 有代码基础，但没做过机器人系统

可以直接从网络与传感器链开始。遇到 `topic`、`action`、`TF`、`QoS`、`lifecycle` 等概念时，页面会在当下完整解释，并链接到更系统的基础页。

### 已经熟悉 ROS 2

可以跳过基础段落，直接看真实脚本、YAML、诊断过程和多楼层应用层。每页的标题和代码块都尽量支持快速检索。

## “项目中的值”和“通用原理”要区分

例如：

```text
192.168.123.222/24    是本项目虚拟机的地址
Go2 网卡不设默认网关  是可迁移的网络设计原则

min_height: 0.1       是现场点云切片参数
按高度过滤点云         是 PointCloud2 转二维扫描的通用方法

inflation_radius: 0.65 是当前场地调参
障碍周围建立代价梯度    是 Nav2 costmap 的通用机制
```

教程会明确区分这两层，避免读者把一组现场值当成所有机器人都适用的标准答案。

## 克隆仓库不等于安装完整环境

`git clone` 会取得代码、地图、配置、图片和文档；它不会自动安装 ROS 2、Nav2、CycloneDDS 或 Unitree 接口。仓库提供：

- 文档环境构建脚本；
- VMware 双网卡配置脚本；
- 运行前检查脚本；
- 拓展坞环境示例文件和依赖清单。

机器人运行端仍需要按环境章节逐层安装和验证。这样比一个不透明的“万能安装脚本”更容易定位问题，也更适合不同版本和硬件条件。
